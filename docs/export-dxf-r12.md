# DXF R12 ASCII Machine Export

`EXPORTDXFR12` writes a separate ASCII DXF R12 (`AC1009`) file intended for
legacy machine controllers and strict CAD importers.

This is a compatibility export, not a replacement for `SAVE` or `SAVEAS`. It
does not modify the open drawing, its path, dirty state, layouts, or undo
history. The default output name is `<drawing>_R12.dxf`.

## First-release geometry contract

The exporter includes model-space `POINT`, `LINE`, `CIRCLE`, `ARC`, legacy 2D
`POLYLINE`, and `LWPOLYLINE`. Lightweight polylines are written as the R12
`POLYLINE/VERTEX/SEQEND` representation with vertex order, closed state,
elevation, widths, and bulges preserved.

Paper-space viewports are omitted. If the model contains another entity type,
the operation stops and reports the complete set of unsupported types. It never
silently drops or approximates geometry. Export a simplified manufacturing copy
when the source contains text, dimensions, hatches, blocks, splines, ellipses,
or 3D/AEC objects.

Entity layer names are preserved. Entity linetypes that cannot be represented
by the minimal R12 profile are changed to `CONTINUOUS` in the exported copy and
reported after a successful export.

## File structure and validation

The output is ASCII DXF with:

- two-line group/value records, CRLF line endings and `$ACADVER=AC1009`;
- finite `$EXTMIN` and `$EXTMAX` calculated from model geometry;
- minimal R12 `LTYPE` and `LAYER` tables;
- no `CLASSES`, `OBJECTS`, `BLOCK_RECORD`, layouts, subclass markers, handles,
  owners, or `LWPOLYLINE` records;
- a terminal `EOF` record.

Group codes and values are emitted as separate ASCII lines. Every line uses
CRLF because the target legacy controller rejected the equivalent binary
AC1009 stream but accepted the same group inventory serialized as ASCII CRLF.

Before delivery, an independent R12 ASCII parser reads the generated bytes and
checks line endings, section balance, `AC1009`, entity inventory, numeric
finiteness and terminal `EOF`. The browser build validates bytes in memory
before starting the download. Native builds write a temporary sibling file and
replace the selected destination only after the export has passed validation.

## Acceptance boundary

Strict byte-level checks do not replace consumer testing. Fusion 360 can accept
some malformed streams that a legacy controller rejects, so the target machine
is the final compatibility boundary. Before rollout, test an anonymized line
and a closed bulged polyline in both consumers. Do not add customer drawings to
the public repository.

The current implementation uses an isolated application-side compatibility
writer because the pinned `acadifc` revision documents R12 but does not model
`AC1009` in `DxfVersion`; its general writer also emits post-R12 sections. The
generic version-model, writer and reader
corrections should be proposed upstream; the command and its fail-safe
manufacturing policy remain in Open CAD Studio.
